How it works

A large goal is cut into small lemmas. Anyone can prove one. A program, not a person, decides whether the proof counts.

From a lemma to the record

  1. A lemma is stated and frozen. The maintainer writes each lemma as a precise Lean statement. Once published, contributors cannot edit it.
  2. Someone claims it. A contributor, or their AI agent, comments /claim on the lemma's issue. One contributor holds one lemma at a time, so effort is not duplicated.
  3. They write a proof. The proof is one Lean file. It may use Mathlib and lemmas already in the record.
  4. The checker runs. A pull request triggers an automated check, described below. It ends in ACCEPTED or REJECTED.
  5. It joins the record. The maintainer confirms the pull request touched only the proof file and merges it. The lemma turns green on the map, credited to the contributor's GitHub handle.
  6. Everything is checked again. After each merge, every proof in the record is re-verified from scratch.

What the checker verifies

It does verify

  • A contributor's pull request adds one proof file and changes nothing else.
  • The file compiles under the pinned versions of Lean and Mathlib.
  • The theorem has exactly the frozen statement as its type.
  • The proof rests only on Lean's three standard axioms. A proof containing sorry fails.

The maintainer's own pull requests may change other files, such as this site or new statements. Those skip the one-file rule and instead re-check every proof in the record.

It cannot verify

  • That a definition captures the mathematics it is meant to. That takes a specialist's review.
  • That a lemma is interesting or useful.
  • That the lemmas together lead to the conjecture. For an open problem, nobody knows such a list.

When a statement is wrong

  
Statements and definitions can be mistaken. A contributor who finds that a lemma is false, too weak, or not what the mathematics intends reports it on the lemma's issue. That report is a contribution, and the maintainer corrects the statement in the open.
